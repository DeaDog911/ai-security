# Задание и данные

## Задача
Регрессия: предсказать оценочную стоимость работ `Valuation` (её определяет департамент) по данным разрешения на строительство в Лос-Анджелесе.
Сценарий применения: проверка адекватности оценки и поиск аномально заниженных или завышенных оценок.
Цель обучения `log1p(Valuation)`. Основная метрика RMSLE; дополнительные: MdAPE и доля прогнозов в пределах ±25%.
Модель: FT-Transformer (собственная реализация на PyTorch), вход — таблица и текст `Work Description`.

## Требования методички (`docs/practice_ai.docx`), кратко
- **Общее:** фиксировать источник и версию данных, split, seed, архитектуру, гиперпараметры, версии библиотек и метрику. 95% CI: Уилсон для долей, bootstrap (B ≥ 2000, лучше BCa) для нелинейных метрик, парный bootstrap для сравнений clean и perturbed.
- **ПР1. Качество данных:** описание датасета; полнота, валидность, уникальность (точные и близкие дубли), train-test leakage, баланс, качество разметки (confident learning / cleanlab на out-of-sample предсказаниях, ручная проверка худших), репрезентативность (MMD с permutation p-value или C2ST), аномалии. Итоговая таблица: свойство | метрика | значение | 95% CI | интерпретация. В выводе указать, какие свойства повлияют на ПР2–ПР4.
- **ПР2. Шум:** не менее 2 типов искажений (для таблиц: шум измерений, пропуски, округление, порча категорий), не менее 4 ненулевых уровней, r ≥ 5 реализаций; robustness curve, ΔM, R_rel, R-AUC (метод трапеций) с bootstrap CI. Для MAE/RMSLE заранее зафиксировать направление интерпретации («меньше — лучше»).
- **ПР3. Adversarial:** threat model (knowledge, goal, access, perturbation space, budget, validity constraints); для таблиц — PGD с маской допустимых признаков или HSJA/surrogate; Validity Rate, robust performance, ASR, R-AUC по ε.
- **ПР4. MIA:** privacy unit (строка или участок/субъект), member и non-member одного распределения, loss-threshold атака (порог подбирается на attack-val, оценка на attack-test); ROC-AUC (стратифицированный bootstrap), Attack Accuracy (Уилсон), TPR@FPR=1%, generalization gap.
- **Итоговый отчёт** по ПР1–ПР4 (раздел 6 методички); выводы условные.

## Bootstrap и доверительные интервалы (`docs/boot.docx`)
- Одна перевыборка: N объектов из N с возвращением. Метрика пересчитывается B раз, **B = 2000 обязательно** (5000 и больше при наличии ресурсов).
- 95% CI: percentile [Q0.025; Q0.975] или, предпочтительно, **BCa** (`scipy.stats.bootstrap(method="BCa")`), особенно при асимметричном распределении метрики.
- **Модель при bootstrap не переобучается:** перевыбираются только объекты тестового набора. Переобучение нужно, только если отдельно изучается вариативность обучения, инициализации или split.
- **Парный bootstrap (ПР2, ПР3):** на каждой итерации один набор индексов применяется сразу к clean- и perturbed-версиям; ΔM_b = M_clean,b − M_perturbed,b. Если 95% CI для ΔM не содержит 0, эффект значим на уровне ≈ 0,05.
- Что перевыбирать в каждой ПР:

| ПР | Что перевыбирать | Метрики | Подход |
|---|---|---|---|
| ПР1 | Объекты датасета | label error rate и др. | Обычный или стратифицированный bootstrap |
| ПР2 | Одни и те же объекты clean/noisy | ΔM(s), R-AUC | Парный bootstrap по объектам |
| ПР3 | Одни и те же объекты clean/adversarial | Robust perf., ASR, R-AUC | Парный; для стохастических атак учитывать seed |
| ПР4 | Members и non-members | ROC-AUC, TPR@FPR | Стратифицированный по двум группам |

- Формат записи результата: «значение; 95% CI = [a; b]».
