Формат: дата — решение — обоснование. Отменённые решения не удаляем, а помечаем ~~зачёркиванием~~ со ссылкой на новое.

## 2026-10-30
- **Задача:** регрессия `log1p(Valuation)`; основная метрика RMSLE (+ MdAPE, доля прогнозов в пределах ±25%). Направление: меньше — лучше.
- **Модель:** FT-Transformer, собственная реализация на PyTorch. Текст `Work Description` подаётся отдельным токеном.
- **LightGBM и бустинги не обучаем** (решение пользователя). Для вспомогательных задач ПР1 (C2ST, IsolationForest) допускается scikit-learn.
- **Предобработку из вводной презентации не берём:** Claude проектирует её сам, решения записываются сюда.
- **Строки с Valuation ≤ 0 или нечисловым значением исключаются из обучения** и учитываются в ПР1 как невалидные метки.
- **Обучение запускает пользователь на своём компьютере** (Windows). Код работает на CUDA и на CPU.
- **Формат результата:** Python-скрипты, которые сохраняют таблицы CSV и графики PNG, плюс Jupyter-ноутбук с разбором.
- **Сессии:** контекст хранится в `CLAUDE.md` и `docs/context/*.md`.
- seed = 42; bootstrap B = 2000.

- **Критерий подозрительной метки (подтверждён):** OOF-прогноз FT-Transformer (5-fold на train), остаток r = log1p(y) − ŷ; метка подозрительна при robust z = 0,6745·(r − median(r)) / MAD(r), если |z| > 3,5 (Iglewicz–Hoaglin). Дополнительно показываем: долю |r| > ln(10), cleanlab.regression score, частоты служебных значений ($501 и т. п.); ручной разбор 20 худших.
- **CI (по `docs/boot.docx`):** доли — Уилсон; остальное — bootstrap по объектам с B = 2000, метод BCa (`scipy.stats.bootstrap`). Percentile — запасной вариант, если BCa неприменим (вырожденное распределение, слишком дорогая метрика); в отчёте указываем, какой метод использован. Модель при bootstrap не переобучается. Для сравнений clean/perturbed (ПР2, ПР3) — парный bootstrap, для MIA (ПР4) — стратифицированный.
- **Железо пользователя:** Windows, AMD Radeon RX 7700 XT (gfx1101, 12 ГБ), 32 ГБ RAM. Основной путь — PyTorch с ROCm для Windows (AMD: ROCm 7.2.1, PyTorch 2.9, Python 3.12, только Windows 11; gfx1101 в списке поддержки). На ROCm GPU виден как `torch.cuda`, поэтому код использует `cuda`, если доступно, иначе CPU. Нужен скрипт проверки устройства. Если ROCm не заработает, запасной вариант — CPU с уменьшенной конфигурацией для 5-fold OOF.

## 2026-10-30 (реализация этапа 0)
- **Устройство:** ROCm на RX 7700 XT работает (`check_device.py`: все тесты OK, обучение быстрее CPU в 128 раз). Обучаем на GPU, AMP float16.
- **Дубли без учёта ID:** ID = `PCIS Permit #`, `Reference # (Old Permit #)`; дубль = совпадение всех остальных исходных столбцов. Удаляются после фильтра Valuation > 0, остаётся первое вхождение (509 строк).
- **Split:** граница между частями проходит по дате (все разрешения одного дня — в одной части): train ≤ 2021-03-18 (242 908), val ≤ 2022-05-02 (52 062), test ≤ 2023-05-19 (51 986).
- **Признаки:** 12 числовых (площади, квартиры, этажи — log1p; lat/lon; год, месяц, день недели, день года выдачи; дни до окончания лицензии; длина описания), 12 категориальных (в т. ч. производный `zone_base` — часть Zone до «-»), текст — TF-IDF (слова 1–2 + char_wb 3–5) → SVD(64). Отрицательные площади, этажи и квартиры считаются пропуском. Клиппинг по квантилям train 0,1%/99,9%; редкие категории (< 10 в train) → OTHER. Исключены также License # (идентификатор), Tract/Block/Lot и адрес объекта (квазиидентификаторы). Год выдачи в test выходит за пределы train и обрезается клиппингом.
- **Пропуски чисел в модели:** вместо отдельных токенов-индикаторов — обучаемый эмбеддинг «пропуск» для каждого числового признака (маска пропуска хранится в признаках).
- **FT-Transformer:** d_token 192, 3 блока, 8 голов, ReGLU FFN 256, attention dropout 0,2, FFN dropout 0,1; голова LN → ReLU → Linear по [CLS]; ≈ 2,1 млн параметров, 26 токенов.
- **Обучение:** AdamW (lr 3e-4, wd 1e-5 без токенизатора/LN/bias), warmup 500 шагов, ReduceLROnPlateau(0,5, patience 2), ранняя остановка по val RMSLE (patience 6, max 60 эпох), batch 512, grad clip 1,0. Цель стандартизуется по train.
- **CI метрик test:** RMSLE и MdAPE — BCa (n ≈ 52k); для n > 60 000 автоматически percentile (jackknife для BCa слишком дорог) — метод пишется в результат. Доля в ±25% — Уилсон (основной) и bootstrap для сравнения.

## 2026-10-31 (реализация ПР1)
- **Рабочая совокупность ПР1:** полнота, валидность и уникальность считаются по трём типам Bldg (760 227 строк, до фильтра VALUATION); leakage, баланс, метки, сдвиг и аномалии — по строкам для обучения (709 309) с их split.
- **OOF:** KFold(5, shuffle, seed 42) по train; в каждом фолде FT-Transformer с гиперпараметрами baseline и ранней остановкой по val; препроцессор — общий, обученный на всём train (метки не использует). Кеш `artifacts/oof_predictions.parquet`. Для val/test остатки считаются по baseline; robust z — по медиане и MAD остатков своей части.
- **cleanlab:** `cleanlab.regression` OUTRE по умолчанию строит kNN с k = 0,5·n (≈ 900 ГБ для n ≈ 5·10⁵), поэтому используется та же функция с k = 100 соседей. Основной критерий меток — robust z (без изменений).
- **Близкие дубли:** тот же APN + оценка Jaccard по MinHash (datasketch, 64 перестановки, символьные 5-граммы нормализованного текста) ≥ 0,9 + стоимость ±10%; считается более поздняя строка пары.
- **MMD:** несмещённая U-статистика (пары объекта с самим собой исключены, в т. ч. повторы в bootstrap-перевыборке — иначе смещённая V-статистика завышается при bootstrap), RBF с медианной эвристикой, подвыборки 5 000 + 5 000, 1 000 перестановок, CI — стратифицированный percentile bootstrap (B = 2000). Контроль — две случайные половины train.
- **C2ST:** логистическая регрессия и MLP(64), 20 000 + 20 000, обучение/оценка 50/50, ROC-AUC с BCa CI (стратифицированный bootstrap по классу); варианты с признаками времени и без.
- **Аномалии:** IsolationForest (300 деревьев, обучение на 200 000 строк train, признаки без времени), аномалия — score ниже 1-го перцентиля train; дополнительно contamination="auto" и выбросы log-цели (|robust z| > 3,5).

- **Обучение бит-воспроизводимо на GPU пользователя** (ROCm 7.2.1, RX 7700 XT): два запуска процедуры baseline с `set_seed(42)` до создания модели дали одинаковые начальные веса, одинаковую историю val RMSLE по эпохам и прогнозы с разницей 0; val RMSLE 0,98162 = сохранённый baseline. - **Разброс между разными seed** ≈ 0,01 val RMSLE (одна пара запусков, грубая оценка). Сравнение MSE и Huber было смешано с разными инициализациями: выигрыш Huber по MdAPE (−5 п.п.) много больше этого разброса, ухудшение RMSLE (+0,02) — того же порядка. Решение «оставить MSE» не меняется.
- **Правило для экспериментов:** `set_seed(SEED)` перед созданием модели; при малых разницах — повторять с 2–3 seed.

## 2026-11-11 (ПР2 — реализация)
- **План ПР2 утверждён** пользователем («Реализуй ПР2 по плану»). Уточнения реализации, не меняющие план:
- **T1:** портятся исходные столбцы, которые видит модель: площадь, высота, DU, ADU (JUNIOR_ADU выброшен препроцессором), координаты и все категории, кроме PERMIT_TYPE; **lat и lon стираются вместе** (одна единица шума — в данных координаты пропадают парой; порознь получился бы невозможный вход). ZONE портится в исходном столбце, производный zone_base следует за ним. Даты, days_to_issue и desc_len не портятся.
- **T2:** заменяются только непустые категории; новое значение — из распределения нормализованных значений train (вместе с редкими, которые модель видит как OTHER). Доля `frac_changed` ниже s, т. к. случайное значение может совпасть с исходным (у флагов HL/EV — почти всегда).
- **X1:** «слово» — последовательность латинских букв длиной ≥ 3 (как токен модели); числа не трогаются. **X2:** удаляется токен модели (буквы или число) вместе с одним соседним пробелом; если удаление склеило бы соседние токены, вставляется пробел. desc_len пересчитывается из искажённого текста.
- **Вспомогательные метрики при r реализациях:** MdAPE — медиана по всем n·r ошибкам (в bootstrap — взвешенная нижняя медиана), доля в ±25% — среднее по объектам долей по реализациям; CI — тот же парный bootstrap (percentile). ΔMdAPE = MdAPE(0) − MdAPE(s), Δ±25% = доля(s) − доля(0): у всех Δ отрицательное — ухудшение.
- **Профиль по признакам:** 11 групп для T1 (4 числовые + 7 категориальных), 7 для T2, r = 5, seed = 42 + 100 000 + 1000·t + 10·g + j; рядом — порча всех признаков типа при s = 0,3 из основной сетки.
- **Прогноз — для всех строк test (с R2) в исходном порядке**, метрики — без R2: так путь совпадает с `train_baseline` и прогноз на чистом test можно сверить бит-в-бит. В полном прогоне несовпадение — остановка; в smoke (подвыборка) — только max |Δ| в журнале.
- **Кеш:** `artifacts/pr2/runs/<ключ>.npy` (+ .json со статистикой шума); `meta.json` хранит md5 модели и препроцессора и строки test — при несовпадении остановка, пересчёт `--force`.
- Smoke ПР2 запускал Claude (инференс на GPU, без обучения); полный прогон — пользователь.
- **Раздел «сдвиг прогноза» (добавлен после полного прогона):** средний остаток log1p(прогноз) − log1p(факт) по уровням шума — в целом, по квартилям VALUATION test без R2 и для обрезанных описаний, CI — парный percentile bootstrap внутри группы (B = 2000). Причина: у X2 RMSLE хуже, а MdAPE и доля в ±25% лучше — разбор показал, что удаление слов сдвигает прогноз вниз и компенсирует завышение baseline на мелких разрешениях. Вывод об устойчивости делаем по RMSLE (основная метрика) с разбором по квартилям стоимости.
