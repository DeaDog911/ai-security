# Журнал решений

Формат: дата — решение — обоснование. Отменённые решения не удаляем, а помечаем ~~зачёркиванием~~ со ссылкой на новое.

## 2026-10-30
- **Задача:** регрессия `log1p(Valuation)`; основная метрика RMSLE (+ MdAPE, доля прогнозов в пределах ±25%). Направление: меньше — лучше.
- **Модель:** FT-Transformer, собственная реализация на PyTorch. Текст `Work Description` подаётся отдельным токеном.
- **LightGBM и бустинги не обучаем** (решение пользователя). Для вспомогательных задач ПР1 (C2ST, IsolationForest) допускается scikit-learn.
- **Предобработку из вводной презентации не берём:** Claude проектирует её сам, решения записываются сюда.
- **Строки с Valuation ≤ 0 или нечисловым значением исключаются из обучения** и учитываются в ПР1 как невалидные метки.
- **Обучение запускает пользователь на своём компьютере** (Windows). Код работает на CUDA и на CPU.
- **Формат результата:** Python-скрипты, которые сохраняют таблицы CSV и графики PNG, плюс Jupyter-ноутбук с разбором.
- **Сессии:** контекст хранится в `CLAUDE.md` и `docs/context/*.md`.
- seed = 42; bootstrap B = 2000.

- **Критерий подозрительной метки (подтверждён):** OOF-прогноз FT-Transformer (5-fold на train), остаток r = log1p(y) − ŷ; метка подозрительна при robust z = 0,6745·(r − median(r)) / MAD(r), если |z| > 3,5 (Iglewicz–Hoaglin). Дополнительно показываем: долю |r| > ln(10), cleanlab.regression score, частоты служебных значений ($501 и т. п.); ручной разбор 20 худших.
- **CI (по `docs/boot.docx`):** доли — Уилсон; остальное — bootstrap по объектам с B = 2000, метод BCa (`scipy.stats.bootstrap`). Percentile — запасной вариант, если BCa неприменим (вырожденное распределение, слишком дорогая метрика); в отчёте указываем, какой метод использован. Модель при bootstrap не переобучается. Для сравнений clean/perturbed (ПР2, ПР3) — парный bootstrap, для MIA (ПР4) — стратифицированный.
- **Железо пользователя:** Windows, AMD Radeon RX 7700 XT (gfx1101, 12 ГБ), 32 ГБ RAM. Основной путь — PyTorch с ROCm для Windows (AMD: ROCm 7.2.1, PyTorch 2.9, Python 3.12, только Windows 11; gfx1101 в списке поддержки). На ROCm GPU виден как `torch.cuda`, поэтому код использует `cuda`, если доступно, иначе CPU. Нужен скрипт проверки устройства. Если ROCm не заработает, запасной вариант — CPU с уменьшенной конфигурацией для 5-fold OOF.
