# План: пересчёт ПР1 на новом baseline (C96 без R2)

Статус: **выполнен** (2026-11-03; учтены два ревью другого агента, утверждён пользователем, полный прогон запускал Claude по разрешению пользователя). Итог — `PROGRESS.md`, решения — `DECISIONS.md`.

## Зачем
С 2026-11-03 baseline — C96, обученный без служебных оценок R2 (VALUATION ∈ {$501, $301} ∪ {≤ $10},
`data.service_mask`). Постановка задачи теперь — «прогноз стоимости для разрешений с несервисной оценкой».
Разделы ПР1, которые используют модель, посчитаны на прежнем C96 и устарели. Прежний C96 и его кеши
лежат в `artifacts/baseline_c96/` (в том числе `oof_predictions.parquet`, `pr1_cls_embeddings.npz`).

## Принцип: какая совокупность в каком разделе
ПР1 — профиль качества **данных**. Служебные оценки — одна из находок ПР1, и правило R2 из неё и вытекает.
Поэтому:
- **Разделы о данных считаются на всех строках, как раньше, и не меняются:** describe, completeness,
  validity, uniqueness, leakage, balance, признаковая часть shift (MMD/C2ST по признакам, KS цели, динамика
  по годам), shift_features, drift_facts, IsolationForest в anomalies. Их числа должны совпасть с текущими
  бит-в-бит, и это проверка, что ничего не сломалось.
- **Разделы об ошибке модели считаются на строках без R2:** новая модель на них не обучалась, а остатки
  на $501 огромны по построению. Если их оставить, label error rate превратится в долю $501.
  Доля R2 показывается отдельной строкой («исключены правилом R2»).

Альтернатива: считать всю ПР1 только без R2. Не рекомендую: тогда пропадает сама находка про $501,
а разделы о данных станут несравнимы с отчётом от 2026-11-01.

## Что меняется в коде (`src/pr1_data_quality.py`)
1. **`compute_oof`:** обучение фолдов и early stopping по val — только на строках без R2, как в
   `train_baseline.py` (`EXCLUDE_SERVICE`). Прогноз делается для **всех** строк train, чтобы формат
   `oof_predictions.parquet` не менялся. Фолды остаются прежние: KFold(5, seed 42) по всем строкам train.
   Тогда разбиение совпадает с прежним OOF, и сравнение «новая модель против C96» получается парным.
2. **`Ctx`:** добавить маску `service` (по VALUATION) для всех строк clean.
3. **`section_labels`:**
   - robust z, порог 3,5, «ошибка > 10 раз», cleanlab, worst20, близкие дубли, RMSLE OOF — на строках без R2
     (медиана и MAD считаются по ним же). Оговорка в тексте: без служебных MAD остатков меньше, порог
     |z| > 3,5 по абсолютной величине строже, поэтому доля подозрительных не сравнима с прежней напрямую —
     сравнение даётся и при прежнем абсолютном пороге;
   - таблица служебных значений (`labels_service_values`): строки о данных (доля $501 и прочих
     служебных по частям) — на всех строках; три строки, которые используют `susp` («подозрительные среди $501»,
     «… среди остальных», «доля $501 среди подозрительных»), при новом определении вырождаются (последняя = 0
     по построению) и заменяются парой «подозрительные среди служебных / среди несервисных» — порог z тот же,
     что для строк без R2 (п. 8);
   - третья панель `labels.png` (по годам): доля подозрительных — без R2, доля служебных — по всем строкам;
     подписи осей и легенды это указывают;
   - новая строка: доля R2 по частям (Уилсон);
   - `labels_model_dependence`: вместо SVD(64) сравнить с прежним C96 (`artifacts/baseline_c96/oof_predictions.parquet`)
     на тех же строках без R2. Это то же сравнение «зависит ли критерий от модели», только с ближайшим соседом.
4. **`section_shift`:**
   - порядок обращений к `rng` не меняется: подвыборки MMD, затем C2ST берутся как раньше, R2 отсекается
     маской уже после выборки. Иначе выборки C2ST сдвинутся и сверка бит-в-бит не пройдёт без реальной ошибки;
   - ошибка по годам (`shift_error_by_year`) — без R2;
   - MMD по [CLS] — на тех же подвыборках, что и раньше (все строки), чтобы сравнение с признаковыми MMD
     осталось на одних объектах; эмбеддинги пересчитываются новой моделью.
5. **`section_anomalies`:** IsolationForest без изменений; ошибка baseline на аномалиях и прочих
   (`anomalies_error`) — test без R2.
6. Подписи в `summary_row` / таблицах: указать срез («без R2»). Интерпретации с числами формируются в коде
   и обновятся сами.

7. **Кеши:** полный прогон с `--force`. Заново считаются OOF, [CLS] и остатки, а с ними MinHash и пары
   близких дублей (≈ 2 мин, результат детерминирован). Защита от повторения: в `pr1_cls_embeddings.npz` и
   рядом с `oof_predictions.parquet` сохраняется md5 `baseline_model.pt` (для OOF ещё и `target_filter`),
   а при загрузке кеш сверяется с текущей моделью: если не совпадает — ошибка с подсказкой `--force`.
   Прежние кеши лежат в `artifacts/baseline_c96/`.
8. **Служебные строки отдельно:** в `labels_suspicious` — строка «подозрительные среди служебных»
   (порог z тот же, что для строк без R2); в `describe_dataset` — строка «исключено правилом R2» по частям.
   Подписи моделей в `labels_model_dependence` берутся из констант, а не задаются в тексте кода.
9. **Попутные исправления** (меняют разделы о данных, поэтому делаются после сверки бит-в-бит, шаг 2):
   - `validity`: пустой ZIP_CODE не считать нарушением формата (это пропуск, он уже есть в completeness);
     в знаменателе «STATUS_DATE < ISSUE_DATE» — только заполненные STATUS_DATE;
   - `shift_text_vocab_by_year`: «обрезано» — если слов в нормализованном тексте больше `word_len`,
     а не ровно `word_len` (по массиву токенов эти случаи не различить, считать по тексту);
   - `labels_model_dependence`: Jaccard наборов подозрительных — в отдельный столбец;
   - `shift_error_by_year`: проверка совпадения `row_id` у OOF и clean (как в `section_labels`).

Не трогаем: слова-токены в представлении для MMD, C2ST и IsolationForest (иначе изменятся разделы,
которые от модели не зависят) и независимость объектов в интервалах (близкие дубли, повторные участки).
И то и другое — оговорки в тексте ноутбука.
