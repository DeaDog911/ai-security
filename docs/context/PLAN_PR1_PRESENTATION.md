## Структура (12 слайдов, ≤ 10 мин)
1. **Титул.** «ПР1. Исследование качества набора данных», команда, гр. 1379, дата.
2. **⟳ Задача, данные, разбиение.** Задача — регрессия `log1p(VALUATION)`, сценарий — проверка адекватности оценки;
   модальность: вход — таблица + текст `WORK_DESC`, выход — одно число; модель — FT-Transformer C96, метрика RMSLE
   (плашка: test RMSLE с CI). Источник — LADBS, 2 набора, выгрузка 30.10.2026. Воронка строк: три типа Bldg →
   VALUATION > 0 → без дублей → без служебных оценок (R2). Хронологический split: полоса 2010 → 2026 с датами границ
   и размерами частей. Источник — `describe_dataset.csv`, `describe_excluded.csv`, `artifacts/metrics.json`.
3. **Признаки и цель.** Число признаков по типам (числовые / категориальные / текст); исключённые признаки и причина
   (ID, квазиидентификаторы, признаки из будущего — `leakage_excluded_features.csv`); `target_distribution.png`
   (пик $501 на графике — мост к разделу меток).
4. **⟳ Полнота и валидность: пропуски структурные, ноль площади — «не указано».** Слева — доля пропущенных ячеек
   и доля объектов с пропуском (CI), пропуск площади у Alter/Repair против New (`completeness.png` или его половина).
   Справа — доля строк с нарушением и три вида нарушений (формат / диапазон / предметная область, по примеру
   на каждый), VALUATION ≤ 0 отдельно (Уилсон). Вывод: эмбеддинг
   «пропуск» в модели; ноль площади — естественный шум (→ тип искажения в ПР2).
   Источник — `completeness_columns.csv`, `completeness_by_type.csv`, `validity.csv`, `validity_overall.csv`.
5. **Уникальность: точных дублей почти нет, близких — несколько процентов.** Схема из трёх условий (тот же APN +
   Jaccard по MinHash ≥ 0,9 + стоимость ±10%), числа: дубли без ID, близкие дубли и вариант по полным APN,
   замаскированные APN; один пример пары из `uniqueness_near_dup_examples.csv`. Источник — `uniqueness.csv`.
6. **Утечка и баланс.** Слева — таблица leakage для val и test: число совпадающих объектов k и доля с CI для каждого
   уровня (копия входа, копия входа и метки, близкий дубль, общий участок). Вывод: копий почти нет, но у большой доли
   test участок есть в train → privacy unit в ПР4. Справа — распределение бинов стоимости train / val / test
   (`balance.png`), IR и нормированная энтропия. Источник — `leakage.csv`, `balance_target_bins.csv`.
7. **⟳ Качество меток: метод и результат.** Схема: 5-fold OOF на train без R2 → остаток r → robust z → |z| > 3,5
   (+ cleanlab, k = 100). Плашки: label error rate (CI), доля ошибок > 10 раз, OOF RMSLE, доля служебных оценок
   (R2) и подозрительные среди них. `labels.png`. Вывод: служебные оценки ($501 и др.) — главный источник шума меток,
   поэтому они исключены из постановки задачи. Источник — `labels_suspicious.csv`, `labels_service_values.csv`,
   `labels_oof_quality.csv`.
8. **⟳ Ручная проверка 20 худших.** Счётчики «проблема метки / неоднозначно / ошибка модели» + 2 характерных примера
   (текст работ, оценка, прогноз). Одна строка: label error rate зависит от модели (Jaccard наборов подозрительных).
   Источник — `labels_worst20.csv`, `labels_model_dependence.csv`.
9. **Train и test различимы.** MMD²_u с permutation p и контролем train/train; C2ST AUC (логрег, MLP) без времени;
   `shift_feature_c2st.png` — какие группы признаков различают сильнее; подгруппы: состав по типам Bldg (χ²), KS цели.
   Источник — `shift_mmd.csv`, `shift_c2st.csv`, `shift_feature_c2st.csv`, `shift_ks_target.csv`.
10. **⟳ Сдвиг во времени и аномалии.** Слева — ошибка по годам с CI (`shift_by_year.png`, `shift_error_by_year.csv`;
    OOF и прогноз вперёд разделены на графике) и 3 факта дрейфа: шаблоны Eplan, новые census tract, рост доли UNK
    (`shift_drift_facts.csv`, `shift_text_vocab_by_year.csv`). Справа — аномалии: критерий текстом (IsolationForest,
    порог — 1-й перцентиль score на train; выбросы log-цели |z| > 3,5), доля аномалий в test против ожидаемого 1%,
    ошибка модели на аномалиях против прочих (`anomalies.csv`, `anomalies_error.csv`).
11. **⟳ Итоговая таблица (п. 2.5 методички).** Таблица на весь слайд, ровно 5 строк образца — см. выше.
    Оформление как в методичке: тёмная шапка, те же названия столбцов.
12. **⟳ Влияние на ПР2–ПР4.** Три колонки:
    - ПР2: M(0) уже содержит шум меток; естественные искажения — пропуски / ноль площади, старение текста, округление;
      парный bootstrap; анализ по подгруппам;
    - ПР3: validity constraints из найденных доменных правил (диапазоны, LA_BBOX, маски допустимых признаков);
    - ПР4: privacy unit — строка или участок (общие участки, близкие дубли, замаскированные APN); non-members нельзя
      брать из хронологических val/test (C2ST AUC высокий).

### Запасные слайды (для вопросов)

- З4. MMD на пальцах: ядро RBF, медианная эвристика, U-статистика, permutation test; MMD по [CLS] — только val vs test.
