# План: дешёвая проверка очистки меток (эксперимент `label_cleaning`)

Статус: черновик 2026-11-02, ждёт утверждения пользователя. Baseline C96 и ПР1 не меняются.

## Вопрос
Даёт ли удаление строк со служебными и административными оценками из обучения прирост качества
сверх простой фильтрации оценки? Если да, имеет смысл обсуждать переобучение baseline (≈ 3,5 ч
вместе с пересчётом ПР1). Если нет, остаёмся с C96 и в отчётах даём метрики на полном и очищенном test.

## Правила очистки (только по метке и тексту, без модели)
- **R2:** VALUATION ≤ $600 (включает служебные $501, $1 и т. п.): train 8,2%, val 9,7%.
- **R3:** административный текст — `supplement|capture|no actual work|extend permit|correct permit|\bfees?\b`
  после `normalize_text`: train 10,2%, val 12,1%.
- **R23 = R2 ∪ R3:** train 13,8%, val 15,5%.

Шаг 0 — **ручная проверка R3** перед запуском. 100 случайных строк train, попавших в R3, но не в R2
(seed 42), размечаются вручную: «работ нет или стоимость не своих работ» или «нормальная оценка».
Если точность R3 < 70%, правило сужается (убираются слова, дающие ложные срабатывания, например `fee`),
и проверка повторяется. Результат — `reports/experiments/label_cleaning/r3_review.csv` с разметкой и итоговой точностью.

## Дизайн
- **Модель — быстрый вариант A** (SVD(64) → 1 токен, `DEFAULT_HP`, `TRAIN_HP`, MSE), ≈ 3,5 мин на запуск.
  Это прокси: C96 читает слова и уже частично распознаёт «supplemental», поэтому её выигрыш от очистки может быть меньше.
- **Протокол как в `text_tokens_holdout`:** val делится по дате (граница 2023-08-17):
  - `val_sel` — ранняя остановка, ReduceLROnPlateau и выбор эпохи;
  - `val_hold` — только оценка.
  
  Test не используется.
- **Варианты** × seed 42, 43, 44 (`set_seed` перед `build_model`):

  | Вариант | train | val_sel (выбор эпохи) |
  |---|---|---|
  | A_full — эталон | полный | полный |
  | A_noR2 | без R2 | без R2 |
  | A_noR23 | без R23 | без R23 |

  A_full уже есть: `artifacts/experiments/text_tokens/holdout/A_s{42,43,44}/`. Сначала проверяю, что прогнозы
  на `val_hold` воспроизводятся (seed 42 — бит-в-бит). При расхождении A_full обучается заново.
  Обучать нужно 6 запусков, ≈ 25 мин GPU.
- Препроцессор и признаки не переобучаются (`artifacts/preprocessor.joblib`, `features.npz`).
  Меняется только набор строк для обучения и выбора эпохи. Стандартизация цели остаётся по полному train:
  это сдвиг, а не изменение модели, и он компенсируется смещением головы.

## Оценка (`val_hold`, ≈ 53 тыс. строк)
Каждую модель оцениваю на четырёх срезах `val_hold`:
1. **полный** — что будет, если очищенную модель применять ко всем разрешениям;
2. **без R2**;
3. **без R23** — основной срез для сценария «оценки с содержательной стоимостью»;
4. **только R23** — цена очистки: насколько хуже модель на исключённых строках.

Метрики: RMSLE (основная), MdAPE, доля прогнозов в пределах ±25%. Парный bootstrap против A_full с тем же seed
(`stats.paired_bootstrap_ci`, B = 2000, percentile). Плюс среднее и разброс по seed, лучшая эпоха, число эпох,
разбивка RMSLE по `PERMIT_TYPE` для seed 42.

**Правило решения** (как в text_tokens): очистка полезна, если на срезе 3 средний ΔRMSLE по seed ≤ −0,02
и CI не содержит 0 при каждом seed. Срезы 1 и 4 — обязательные оговорки к выводу, не критерий.

## Реализация
- `src/experiments/label_cleaning.py` повторно использует функции `text_tokens_holdout`
  (`split_val`, `inputs`, сохранение прогнозов по эпохам). Ключи `--variants`, `--seeds`, `--force`, `--report`.
  Идемпотентно: готовые запуски в `artifacts/experiments/label_cleaning/<вариант>_s<seed>/` не пересчитываются.
- Правила R2/R3 — одна функция с регуляркой в константе, общая для эксперимента и (при принятии) для `data.py`.
- Smoke: 5000 строк train, 2 эпохи для A_noR23. Затем полные запуски в фоне с логом `artifacts/logs/label_cleaning.log`.
- Отчёт: `reports/experiments/label_cleaning/` — `results.csv`, `paired_vs_full.csv`, `by_type.csv`, `summary.md`.
  Все числа из `summary.md` должны быть в CSV (правило `check_notebook_numbers`).
- Код и результаты — отдельными коммитами; артефакты не коммитятся.
- По завершении обновляются `PROGRESS.md` и `DECISIONS.md` (методика и правила R2/R3 с датой).

## Время
Шаг 0 (ручная разметка) — ≈ 15 мин; код и smoke — ≈ 20 мин; 6 запусков — ≈ 25 мин GPU; отчёт — ≈ 10 мин.
Итого ≈ 1–1,5 ч. GPU не должен быть занят другой вкладкой.

## Чем заканчивается
Таблица результатов и вывод с остановкой — без изменения baseline. Если правило решения выполнено, оцениваю,
что нужно для принятия: при желании подтверждающий запуск C96 на очищенном train (1 seed, ≈ 30 мин),
затем переобучение baseline, пересчёт ПР1 (OOF ≈ 2,5 ч) и переисполнение ноутбука. Решение принимает пользователь.
